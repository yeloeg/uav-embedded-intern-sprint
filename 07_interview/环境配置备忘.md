## 二、从零恢复（换电脑照这个顺序做）

1. 装 Git for Windows（一路默认），装 VS Code。
2. 下载 w64devkit：`github.com/skeeto/w64devkit/releases` 里的 `w64devkit-x64-*.7z.exe`（约 59 MB），
   解压到 `D:\w64devkit`（**路径别带空格和中文**）。
3. 把 `D:\w64devkit\bin` 加进用户 PATH：

   ```powershell
   [Environment]::SetEnvironmentVariable("Path", ([Environment]::GetEnvironmentVariable("Path","User").TrimEnd(';') + ";D:\w64devkit\bin"), "User")
   ```

   关掉所有终端重新打开，用 `gcc --version` 验证。
4. 生成 SSH key 并加到 GitHub：

   ```powershell
   ssh-keygen -t ed25519 -C "3198455020@qq.com"
   type $env:USERPROFILE\.ssh\id_ed25519.pub    # 复制整行 → GitHub → Settings → SSH and GPG keys
   ```

5. **关键一步**：让 Git 使用 Windows 自带的 OpenSSH（不加这行，`git push` 必定失败，原因见坑 2）

   ```powershell
   git config --global core.sshCommand "C:/Windows/System32/OpenSSH/ssh.exe"
   ```

6. 克隆仓库：`git clone git@github.com:yeloeg/uav-embedded-intern-sprint.git`

## 三、踩过的坑（含排查过程）

### 坑 1 · git push 报 `Failed to connect to github.com:443`

**现象**

```
fatal: unable to access 'https://github.com/...': Failed to connect to github.com:443 after 21090 ms: Could not connect to server
```

**排查**：分端口测连通性（`Test-NetConnection <主机> -Port <端口>`）

| 目标 | 结果 |
|---|---|
| `github.com:443`（HTTPS，原来 push 走的通道） | ❌ 不通 |
| `github.com:22`（SSH） | ✅ 通 |
| `ssh.github.com:443`（SSH over 443） | ✅ 通 |
| `gitee.com:443`、`baidu.com:443`（对照） | ✅ 通 |

**结论**：本机网络正常，是 GitHub 的 HTTPS(443) 通道不通，而 SSH 通道可用。

**解决**：远端从 HTTPS 换成 SSH

```powershell
git remote set-url origin git@github.com:yeloeg/uav-embedded-intern-sprint.git
```

**经验**：连不上 GitHub 时，第一件事是**分端口测连通性**，别急着怀疑配置。
SSH 的 22 端口被挡时，还可以改走 `ssh.github.com:443`。

### 坑 2 · `Permission denied (publickey)`，报错里出现一串八进制数字

**现象**

```
Could not create directory '/c/Users/267/353/274/322/307/277/.ssh' (No such file or directory).
Failed to add the host to the list of known_hosts
git@github.com: Permission denied (publickey).
```

**排查**：对比两套 ssh 对 HOME 的解析结果

```
D:\Git\usr\bin\ssh.exe               → /c/Users/<乱码>/.ssh/known_hosts   ← 中文被转义
C:\WINDOWS\System32\OpenSSH\ssh.exe  → 正常路径
```

**根因**：Windows 用户名 `冯家强` 是中文，而 **Git 自带的是 MSYS 版 ssh，处理不了中文路径**——
它把用户名按 GBK 编码后转义成八进制，`267 353 274 322 307 277` 正是"冯家强"三个字的 GBK 字节
（B7 EB / BC D2 / C7 BF）。于是它跑去一个根本不存在的目录找密钥，认证自然失败。

**迷惑点**：手动敲 `ssh -T git@github.com` 是通的（用的是 Windows 自带 ssh），
但 `git push` 失败（Git 调的是自己捆绑的那一套）——**同一个命令名，两个不同的程序**。

**解决**（一行）

```powershell
git config --global core.sshCommand "C:/Windows/System32/OpenSSH/ssh.exe"
```

**验证**

```
ssh -T git@github.com
→ Hi yeloeg! You've successfully authenticated, but GitHub does not provide shell access.

git push
→ b2524b4..6adf576  main -> main
```

**经验**：工具链和用户目录尽量避开中文路径；同名工具共存时，先确认"到底在用哪一个"。

### 坑 3 · PATH 里堆了 11 条失效 / 重复 / 危险条目

**现象**：系统 PATH 29 条，其中 11 条有问题（清理后 29 → 18 条）。

| 条目 | 问题 |
|---|---|
| `D:\新`、`文件夹\`、`WINDOWS\system32`、`C:` | 中文路径被程序重写时截断成的碎片。其中 `C:` 是**裸盘符**，等于把"当前目录"加进搜索路径，属于安全隐患 |
| `C:\Users\Administrator\AppData\Local\Microsoft\WindowsApps` | Administrator 账户已不存在 |
| `D:\VScode\mingw64\bin` | MinGW 已删除，只剩路径记录 |
| `C:\Program Files (x86)\Windows Kits\10\Windows Performance Toolkit\` | 该组件未安装 |
| `C:\WINDOWS`、`...\System32\Wbem`、`...\WindowsPowerShell\v1.0\`、`...\OpenSSH\` | 与 `%SystemRoot%` 系列重复 |

**解决**：先只读体检 → 备份（同时生成人眼可读的 `.txt` 和双击可回滚的 `.reg`）→ 再清理。
备份文件已验证能 100% 还原原始值（838 字符、29 条逐字符一致）。

**经验**

- **卸载软件一定走卸载程序**（设置 → 应用）。直接删文件夹 = 文件没了、PATH 记录还在，这次 11 条多半就是这么来的
- 安装时留意 **Add to PATH** 勾选项；能改用户 PATH 就别动系统 PATH
- **不要用 `setx` 改 PATH**：超过 1024 字符会被截断，还会把 `%变量%` 展开成硬编码
- 每 3 个月体检一次 PATH，别攒到几十条再动

## 四、面试怎么讲（30 秒版）

> 配开发环境时遇到一个典型问题：`git push` 报认证失败，但手动 `ssh -T git@github.com` 却是通的。
> 我先分端口测连通性，发现 GitHub 的 HTTPS 通道不通、SSH 通道正常，于是把远端换成 SSH；
> 结果又报 `Permission denied`，而且报错路径里出现一串八进制数字。我对比了两套 ssh 对 HOME 的解析，
> 定位到根因是 Windows 用户名是中文，Git 自带的 MSYS 版 ssh 把中文路径转义成了无效路径。
> 让 Git 改用 Windows 原生 OpenSSH 后，一行配置解决。
> 顺手还把系统 PATH 里 11 条失效 / 重复 / 危险项清理干净，并做成了可双击回滚的备份格式。
