## 二、今天踩的两个坑（比答案更值钱）

### 坑 1 · `else` 放进了查找循环里 → 只有第一条命令能用

**错误写法**：

```c
for (int i = 0; i < g_cmd_count; i++) {
    if (strcmp(argv[0], g_cmds[i].name) == 0) { ...; return 0; }
    else { printf("未知命令..."); return -1; }   /* ← 循环第一次没比中就返回了 */
}
```

**现象**：排在第一位的 `help` 正常，`led` / `echo` / `sys` 全被判成"未知命令"。

**原因**：循环**第一次**比较不中就直接 `return -1`，后面的表项根本没机会被检查。

**正确思路**：**"没找到"是循环跑完之后才能下的结论** —— 判断"不存在"必须放在循环外面。

**能迁移的经验**：凡是"遍历查找"的代码，都要先问自己一句——
"我这个'没找到'的判断，是在循环里还是循环外？"

### 坑 2 · 同一个函数定义了两遍

```
main.c:129:13: error: redefinition of 'cmd_echo'
main.c:120:13: note: previous definition of 'cmd_echo'
```

一个源文件里不允许同名函数定义两次。删掉多余的那份即可。

### 附带的一个警告

```
warning: control reaches end of non-void function [-Wreturn-type]
```

函数声明返回 `int`，就必须保证**所有执行路径**都有返回值。`dispatch` 最后那个 `return -1;` 别漏。

## 三、收工前回答 1：用函数指针表分发，比一长串 `if / else if` 好在哪？

### 🎤 30 秒口述版

> 最大的好处是**扩展不用改逻辑**。用 `if / else if` 的话，每加一个命令都要往分发函数里塞一条分支，
> 分发函数的代码量和命令数一起长；换成命令表之后，命令名、处理函数、帮助文本都集中在表里，
> **加一条命令只需要在表里加一行，分发逻辑一个字都不用动**。
>
> 第二个好处是**信息集中**：想知道这个程序支持哪些命令，看一眼表就行，不用通读整个分发函数。
> 顺带的，`help` 命令可以直接遍历表自动生成，不用手动维护一份帮助文本——两者永远不会不一致。
>
> 第三个好处是**可以做批量处理**：因为是数据，所以能遍历，
> 比如给所有命令统一加权限检查、统计每个命令的调用次数、或者按前缀分组。
>
> 飞控里这套结构到处都是：MAVLink 按消息 ID 分发到不同处理函数、地面站命令表、参数表，都是表驱动。

### 机制拆解

**① 对比一下代码结构**

```c
/* 写法 A：if / else if —— 每加一条命令都要改这里 */
if      (strcmp(cmd, "help") == 0) cmd_help(argc, argv);
else if (strcmp(cmd, "echo") == 0) cmd_echo(argc, argv);
else if (strcmp(cmd, "led")  == 0) cmd_led(argc, argv);
/* ... 再来 20 条命令，这个函数就有 20 层分支 */
else printf("未知命令\n");

/* 写法 B：表驱动 —— 分发只有一遍循环，永远不变 */
for (int i = 0; i < g_cmd_count; i++) {
    if (strcmp(g_cmds[i].name, argv[0]) == 0) {
        g_cmds[i].handler(argc, argv);
        return 0;
    }
}
printf("未知命令\n");
```

**② 表驱动的代价（要能说出来，才显得真懂）**

1. **统一签名**：所有处理函数的参数和返回值必须一致（这正是 `typedef void (*cmd_handler_t)(int, char**)` 存在的意义）。
   如果某个命令需要额外参数或要返回结果，就得想办法（比如全局状态、参数解析、或改统一签名）。
2. **编译期检查变弱**：表里的命令名是字符串，写错了编译器不会报错，只有运行时才发现。
   缓解办法：写单元测试，或者用宏生成表项。
3. **调试时多一跳**：调试器里不能直接从 `dispatch` 跳到 `cmd_led`，得先看表里的指针值。

### 可能被追问

| 追问 | 怎么答 |
|---|---|
| `if / else if` 什么时候反而更好？ | 分支很少（2-3 条）且逻辑各不相同、参数签名不统一时，直接写分支更直观 |
| 表驱动的本质是什么？ | **把"代码结构"变成"数据"**——控制流的分支变成可以被遍历、被检查、被生成的数据 |
| 怎么让命令支持别名（`quit` 和 `exit` 等价）？ | 在表里加两行，指向同一个 handler（见下面第 3 题） |
| 表里的函数指针什么时候确定？ | 编译期就确定了，放在只读数据段；也可以设计成运行时可换（比如按模式切换不同的处理函数集） |
| 飞控里为什么更需要表驱动？ | MAVLink 有上百种消息，用分支写不现实；而且表可以被工具扫描出来生成文档 |

### 🧠 记忆钩子

> **分支是逻辑，表是数据；能变成数据的东西，才好扩展。**

## 四、收工前回答 2：`int (*f)(int, char**)` 这种声明，怎么一眼读出它是函数指针？

### 🎤 30 秒口述版

> 看**名字跟谁先结合**。C 的声明规则是"先看括号，再看括号右边，最后看左边"。
>
> `int (*f)(int, char**)` 里，`f` 被括号包着、先和 `*` 结合，所以 **f 是指针**；
> 然后看括号右边是 `(int, char**)`，说明它指向一个接收这两个参数的函数；
> 最后看最左边的 `int`，那是函数返回值类型。连起来读就是——
> "f 是一个指针，指向接收 `(int, char**)`、返回 `int` 的函数"。
>
> 对比一下 `int *f(int, char**)`：这里 `f` 后面直接跟括号，**先和 `()` 结合**，所以 f 是一个函数，
> 返回值是 `int*`。同样三个东西，**括号一挪，意思完全变了**。
>
> 我自己的记法是：**名字旁边有 `*` 且有括号包裹 → 它是指针；名字后面直接跟 `()` → 它是函数**。

### 机制拆解的三个对照

```c
int (*f)(int, char**);     /* f 是指针 → 指向「(int,char**) → int」的函数 */
int *f(int, char**);       /* f 是函数 → 返回 int*                        */
int (*f[3])(int, char**);  /* f 是数组 → 3 个元素，每个都是函数指针        */
```

读法口诀（从里往外）：

1. 找到名字 `f`
2. 看它**先和谁结合**：被括号包住的 `*` → 指针；直接跟 `()` → 函数；跟 `[]` → 数组
3. 然后逐层往外：参数是什么、返回类型是什么

**实际工程里更常见的写法**——先用 `typedef` 起个名字，就再也不用读这种绕人的声明了：

```c
typedef int (*op_fn)(int, int);   /* 以后直接写 op_fn，一眼就懂 */
```

### 可能被追问

| 追问 | 怎么答 |
|---|---|
| 函数指针赋值为什么不用写 `&`？ | 函数名在表达式里本来就会退化成函数地址，`f = op_add;` 和 `f = &op_add;` 等价，前者更常见 |
| 调用时为什么不用写 `*`？ | `f(3,4)` 会被编译器理解成 `(*f)(3,4)`，两种写法都合法，前者更常写 |
| 为什么不能写 `int f(int, char**);` 然后再赋别的函数？ | 那是**函数声明**不是变量，函数名不能被重新赋值；要"可替换"就必须用函数指针变量 |
| 空指针调用会怎样？ | 崩溃（未定义行为）。工程上调用前要判断 `if (handler != NULL)` |

### 🧠 记忆钩子

> **括号里的 `*` = 指针；名字后面直接跟 `()` = 函数。**

## 五、收工前回答 3：想让 `quit` 和 `exit` 等价，命令表要怎么改？

### 🎤 30 秒口述版

> 现在 `quit` / `exit` 是在 `main` 里用两句 `strcmp` 硬判断的，等于给它们开了"特殊通道"。
> 想让它们等价、又不破坏表驱动的结构，最直接的做法是**在命令表里加两行，指向同一个处理函数**：
>
> ```c
> {"quit", cmd_quit, "quit  退出"},
> {"exit", cmd_quit, "exit  退出（quit 的别名）"},
> ```
>
> 然后把退出逻辑挪进 `cmd_quit`，`main` 里那两句 `strcmp` 就可以删掉——
> 主循环只剩下"读一行 → 切词 → 分发"三件事，没有任何特例分支。
>
> 这里会撞上一个设计问题：handler 现在的签名是 `void (*)(int, char**)`，没有返回值，
> 那它怎么告诉主循环"我要退出"？两种常见做法：
> 一是用一个全局状态变量（比如 `g_running`），handler 改它、主循环检查它；
> 二是把 handler 的签名改成带返回值（比如返回 `int`，约定非 0 表示要退出）。
> 前者改动小但引入全局状态，后者更干净但要统一改所有 handler——
> 这就是"统一函数签名"这个设计约束的真实代价。

### 两种改法对比

| 改法 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 表里加别名行** | 两行指向同一个 `cmd_quit` | 改动最小，保持表驱动 | 需要"退出"这个跨层信息传递机制 |
| **B. 给 `command_t` 加字段** | 比如加 `const char *alias;` | 语义更清楚，一个命令写一行 | 表结构变复杂，分发要多比一次 |

（实际工程里 A 最常用：别名就是多加一行。）

### 可能被追问

| 追问 | 怎么答 |
|---|---|
| 为什么 `quit` 也放进表里更好？ | 让主循环没有特例分支，控制流统一；`help` 也能自动列出它 |
| 别名会不会让 `help` 显示两遍？ | 会。想只显示一次，可以给表加个 `hidden` 标志，或者让别名行不填 help 文本 |
| 这个"handler 要告诉主循环退出"的问题，叫什么？ | 本质是**控制流反向传递**——底层函数想影响上层流程，通常用返回值或状态变量，而不是直接跳转 |
| 飞控里有没有类似需求？ | 有。比如"收到重启命令要复位"、"进入校准模式要切状态机"——都是 handler 需要改变系统状态 |

### 🧠 记忆钩子

> **想让两个命令等价，不是写两遍逻辑，而是让表里两行指向同一个函数。**

## 六、附加：切词的三句话（顺手记一下）

1. **为什么要 `char **argv`**：每段用 `char *` 指向，装这些指针的数组作参数时退化成指向首元素的指针，所以是 `char **`。
2. **空格去哪了**：被**就地改写成了 `'\0'`**——没有复制任何数据，`argv[i]` 指向的仍然是原字符串内部的位置。
3. **为什么 `line` 必须是数组**：因为要就地改它。传字符串字面量（`const char *`）进去会崩——
   这也是 `main` 里必须写 `char line[MAX_LINE]` 而不是 `char *line = "..."` 的原因。

### 🧠 记忆钩子

> **切词不搬数据，只把分隔符改成 `'\0'`。**
