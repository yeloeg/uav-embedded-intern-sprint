# W1D3 前置知识清单

> **先说结论**：W1D3 看起来陌生，其实只多了 **一个新概念——函数指针**。
> 命令表本身就是"一个结构体数组，其中有个成员是函数指针"；遍历数组、比字符串，你都已经会了。
> 下面是完整清单，从"你已经有"到"必须补"，按优先级排好。

---

## 一、你已经会的（来自 W1D1 / W1D2，不用重学）

| 已经用过的东西 | 在哪里用过 | W1D3 里怎么复用 |
|---|---|---|
| 指针、取地址 `&`、解引用 `*` | `swap_int(&a, &b)` | `argv[]` 里存的就是指针 |
| 结构体 + 成员访问 `->` / `.` | `ring_buffer_t`、`rb->head` | `command_t` 表、`g_cmds[i].name` |
| 数组与下标 | `uint8_t buf[RB_SIZE]` | 命令表就是一个结构体数组 |
| `const` | `const ring_buffer_t *rb` | `const char *name` |
| `sizeof` 求元素个数 | `sizeof(rb->buf)` | `sizeof(g_cmds) / sizeof(g_cmds[0])` |
| `size_t` / `uint32_t` | 位操作、环形缓冲区下标 | 下标、计数 |
| 循环遍历数组 | 遍历 `buf[]` | 遍历命令表 |

**所以，命令表你可以这样理解：**

```c
struct {
    const char *name;      /* 命令名，比如 "led" */
    void (*handler)(...);  /* 处理这个命令的函数 —— 唯一的新东西 */
} g_cmds[] = { ... };      /* 一个数组，每个元素 = 一条命令 */
```

`dispatch()` 要做的就三件事：**遍历数组 → 用 `strcmp` 比名字 → 命中就调用那个函数指针**。
前两件你已经会了，第三件就是下面第 1 条。

## 二、必须补的（按优先级）

### ① 函数指针 —— 唯一真正的新概念（约 15 分钟）

**是什么**：把"函数"当成数据存进一个变量，之后通过这个变量调用它。

**声明读法**（从左往右、从里往外读）：

```c
int (*f)(int, int);
/*  ^^^^  ^   
   f 是一个指针 → 指向"接收两个 int、返回 int"的函数 */
```

**三条语法要点**：

1. 赋值时**不写** `&`：`f = op_add;`（函数名本身就是地址）
2. 调用时**不写** `*`：`f(3, 4)` 和 `(*f)(3, 4)` 完全等价
3. 括号不能省：`int (*f)(int,int)` 是"函数指针变量"，`int *f(int,int)` 是"返回 int* 的函数"——差一个括号，意思天差地别

**自测**：不查资料，写出"接收一个 `int`、返回一个 `int`"的函数指针声明。
（答案：`int (*f)(int);`）

→ 对应热身代码**例 1**

### ② 字符串切词与 `char **argv`（约 15 分钟）

**为什么需要"指针的指针"**：一行命令要切成好几段，每段用 `char *` 指向它的开头；
于是需要"一个存放 `char *` 的数组"。而数组作为函数参数会退化成"指向首元素的指针"，
首元素本身是 `char *`，所以参数类型就是 `char **`。

```c
char  line[]  = "led on 3";   /* 原始字符串：可以改，所以定义成数组而不是指针 */
char *argv[8];                /* 8 个槽位，每个放一个"段开头"的地址 */
/*    ↑
    argv[0] → "led"
    argv[1] → "on"
    argv[2] → "3"
*/
```

**切词的本质三步**：找段首 → 找段尾 → 把段尾那个空格改成 `'\0'` 封口，然后继续。

**顺带认识的库函数**（看代码时遇到不至于懵）：

- `fgets(buf, size, stdin)`：安全地读一行（比 `gets` 安全，会带上换行符）
- `strcspn(s, "\r\n")`：找第一个换行符的位置，常用来砍掉行尾换行
- `strtok(s, " ")`：库函数版的切词（会改写原字符串，连续分隔符的处理和手写的略有不同）

**自测**：为什么函数参数写 `char *argv[]` 和 `char **argv` 是一回事？

→ 对应热身代码**例 3**

### ③ 字符串比较 `strcmp`（约 5 分钟）

**为什么不能写 `if (name == "help")`**：那样比的是两个**地址**，不是内容。两个内容相同的字符串，
地址几乎总是不一样，所以判断永远是假。

```c
if (strcmp(name, "help") == 0)   /* 0 表示内容完全相同 */
```

**记忆**：`strcmp` 返回 0 是"相等"，所以判断要写 `== 0`——这是初学者最容易写反的地方。

→ 对应热身代码**例 4**

### ④ `typedef` 给函数指针起短名字（约 5 分钟）

骨架代码里用了它，看不懂会卡住：

```c
typedef void (*cmd_handler_t)(int argc, char **argv);
/*   ^^^^   ^^^^^^^^^^^^^^  ^
     别名        指针变量名    参数 */

cmd_handler_t handler;   /* 等价于 void (*handler)(int, char **argv); */
```

**自测**：`cmd_handler_t f;` 声明了一个什么？答：一个函数指针变量，指向"接收 `(int, char**)`、返回 `void`"的函数。

## 三、知道个大概就行（不影响你动手）

| 概念 | 一句话 | 什么时候真正用到 |
|---|---|---|
| 回调（callback） | 把函数指针交给别人，让别人在合适的时机调用你 | 命令表的 handler 就是回调 |
| 表驱动 vs `switch` | 新增命令只改表里一行，分发逻辑一行都不用动 | W1D3 的设计核心 |
| `static` 函数 | 只在本文件内可见，别的文件调不到 | 骨架里所有命令处理函数都是 `static` |
| 输出缓冲 | `printf` 是带缓冲的，`fflush(stdout)` 保证提示符立刻显示 | 交互式 CLI 不用会"看不到提示符" |
| `const char *` | 指向的内容不可改（字符串字面量就是这种） | `command_t` 的 `name` 字段 |

## 六、运行程序时中文变乱码怎么办

**现象**：程序能跑、逻辑也对（数字、`add` / `mul` 这些都对），
但中文输出变成 `渚� 1锛氬嚱鏁版寚閽�` 这种看不懂的东西。

**原因**：程序输出的是 **UTF-8 字节**，而你的终端按 **GBK(936)** 去解码，两边对不上。
（和之前 `.cmd` / `.ps1` 文件的乱码是同一类问题。）

### 最快的解法：先切代码页再运行

```powershell
chcp 65001
.\01_c\w1d3\warmup.exe
```

`chcp 65001` 把当前终端切成 UTF-8，之后所有输出了 UTF-8 的程序都能正常显示。
**只需要在每次新开终端后执行一次**，同一个窗口里后续运行都不用再敲。

### 一劳永逸：让每个新开的 PowerShell 自动切

```powershell
New-Item -Path $PROFILE -ItemType File -Force | Out-Null
Add-Content -Path $PROFILE -Value 'chcp 65001 > $null'
```

然后关掉终端重新打开即可（VS Code 里的终端也会生效）。

> 副作用提醒：少数老工具输出的是 GBK 字节，切到 65001 后它们反而会乱码。
> 真遇到了，在窗口里临时 `chcp 936` 切回来就行。
>
> 如果切到 65001 后中文变成「方框」，那是**终端字体**没有中文字形，
> 换个等宽中文字体（比如 Sarasa Mono SC），或者改用 Windows Terminal。

### 为什么不能把源码或输出改成 GBK

我在这台机器上实测过，你的工具链（w64devkit 的 GCC）**没带 iconv**，转换不了：

```
gcc -fexec-charset=GBK   → error: no iconv implementation, cannot convert from UTF-8 to GBK
gcc -finput-charset=GBK  → error: no iconv implementation, cannot convert from GBK to UTF-8
```

所以只有一条正路：**源码保持 UTF-8 + 终端切成 UTF-8**。

顺带说一句，UTF-8 也是 GitHub、Linux、嵌入式工具链的通用标准。
**千万别为了显示正常，去把 `.c` 文件另存成 ANSI/GBK**——那样代码传到 GitHub 上、
或者以后换成 Keil / STM32CubeIDE 编译时，注释和字符串都会出问题，等于给自己挖坑。
